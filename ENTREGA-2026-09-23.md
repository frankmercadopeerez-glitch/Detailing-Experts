3. Registro por correo: falta prueba real de entrega de verificación, recuperación y acceso como cliente nuevo, además de vinculación administrativa supervisada a un historial. No se modificaron contraseñas ni permisos reales para simularla.
4. Dispositivos físicos: falta prueba de instalación y recepción push en Android/iPhone, teclado, cámara/HEIC y navegadores Safari/Firefox. La emulación responsive no sustituye esas pruebas.
5. Operación: definir responsables y permisos si se quieren roles distintos de administrador/cliente; confirmar número real de puestos de atención. El formulario admite hasta cuatro y usa uno por defecto.
6. Datos: la eliminación definitiva y la revisión de cargas ambiguas siguen siendo asistidas; ocultar/archivar es reversible. Falta un respaldo externo periódico de Authentication y originales ImageKit, con política de retención acordada.
7. Rendimiento: no se presenta una puntuación Lighthouse ni Core Web Vitals como medida en esta entrega. Para historiales muy grandes conviene mover búsqueda/totales al servidor; actualmente se recorren todas las páginas y se conserva la vista previa si una carga falla.
